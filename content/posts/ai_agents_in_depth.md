前几周在刷 X/Twitter 的时候，看见李博杰在推自己的新书《AI Agents in Depth》。

![img](/img/2026/08/libojie.png)

本来不是特别想入坑，因为之前看过一些 Agent 研发相关的教程，觉得对于上下文工程、工具、Agent Loop 等都有一定的认识。但是，看了一眼目录以后还是被吸引了：除了常见的构建 Agent 的知识，还有 Agent 评估、多模态与实时交互、Agent 的持续进化等我自己比较感兴趣、还在研究的内容，也就不知不觉入坑看了起来，甚至还推荐给了同事。

今天看完了，这里倒不是想分享技术方面的内容，更多还是想说说我在读这本书的过程中的一些感悟。

## 一、对于天才少年的感慨

恕我孤陋寡闻，知道李博杰还是因为他在 Twitter/X 上炮轰 DeepSeek 的面试流程，后来就开始关注他的动态，直到读了这本书，我可能才对他为什么叫天才少年有了一定的感知。

这本书里面不仅包含了 Agent 构建工程方面的内容，还有大量关于 AI/LLM/Agent 的前沿研究内容，能把工程和研究两者结合起来，并在书里面娓娓道来，确实彰显了他的实力。后来我了解到，他的专业其实主要是在网络系统而不是人工智能，半路出家还能快速达到这种水平，我只能表示 orz 了。

## 二、纸上得来终觉浅

上一个能给我这种感觉的还是季逸超：做研究而不木讷，做技术还非常有产品思维……遂我一直有个疑问，他们到底是怎么做到的，一方面在领域内有深刻的认知，另外一方面仿佛半个圈子（夸张）都是他们的好友。所以我问了 Kimi：

> Hualet: Manus 季逸超和 Pine AI 的李博杰，为什么他们的理论和工程功底都那么好？尤其是李博杰感觉横跨几个领域，有什么值得学习的地方？

> Kimi:
>
> **为什么他们"理论+工程"双修**
>
> 季逸超是典型的"工程倒逼理论"路径。他初中开始研究操作系统开发，高中独立写出猛犸浏览器和手势输入法 Rasgueado 赚到第一桶金，大学时做 Magi 知识搜索引擎。他的理论功底不是从教科书里来的，而是产品一次次撞到天花板后被迫去补的——做搜索引擎必须懂信息检索和知识图谱，做 Manus 必须懂 Agent 架构和推理模型（所以他会自己开源 Steiner 推理模型）。这类人的特点是：理论永远服务于一个具体的、要交付的系统，所以学得极深且极实用。
>
> 李博杰是罕见的"学术全栈"路径，这也是你感觉他横跨几个领域的原因。看他的论文发表阵地就明白了：SIGCOMM（网络）、SOSP/OSDI（操作系统）、NSDI（网络系统）、ATC、PLDI（编程语言）——正常人博士生涯能在一个顶会发几篇就很强了，他横跨了系统领域几乎全部的顶级会议。在华为他做的是大模型训练软硬协同和基础设施优化、灵衢 UB 互联架构，这要求同时懂分布式系统、网络协议、编译器、硬件。加上微软亚洲研究院的训练（MSRA 的传统就是要求博士生"论文能发、代码能跑、系统能上线"），他的知识体系是"垂直贯通"的：从应用层 Agent 到框架到互联协议到芯片，每一层都亲手做过。
>
> **共同点才是真正值得学的**
>
> **都在极早期就建立了"完整闭环"的经验。** 季逸超高中时一个人完成设计、开发、宣传片、配音；李博杰博士期间从问题定义到系统实现到论文写作全程自己扛。闭环经验让人对"一个东西从想法到落地"的每个环节有直觉，这是跨领域的真正基础——所谓横跨，本质是抽象能力在多个领域的复用。
>
> **理论是被真实问题驱动的。** 两人都不是"先学完再动手"。李博杰离开 Pine AI 的理由很典型：他说在基础模型公司之外做应用层，数据构造、训练技巧这些关键信息拿不到，所以要去离"智能上限"更近的地方。他是在认知边界被卡住之后，主动把自己挪到信息密度最高的位置。
>
> **逆共识下注，靠判断而非跟风。** 李博杰两次职业选择都是逆势：2025 年大家追预训练时他去做 Agent 应用，2026 年 Agent 最热时他转向基础模型。季逸超做 Magi 搜索引擎、做通用 Agent，也都不是当时的主流叙事。跨领域能力强的人往往如此——因为他们能看到多个领域，所以比单一领域的人更早识别真正的结构性机会。

工程都倒逼到理论环节了，那不就是只有领域 top 才能做到的嘛，这就是他们成功的路径……大模型来了以后，软件行业的同仁都非常焦虑会被 AI 替代掉，但是这两年虽然 LLM、Agent、Harness、Loop 的进一步增强，能做的事情更多更好了，我仍然能看到人在软件工程中输入的价值、做设计的价值、做 Harness/Loop 工程的价值等等。而且我想，光焦虑是没有用的，还是要加强自己的专业长板，不断加长到行业 top，除非行业没有了，否则永远有你的一席之地。

## 三、终身学习

刚好前两天跟同事聊天，聊到了关于技术认知深度的问题，我们不约而同地感慨：一方面还是要持续不断地学习，另一方面在学习的过程中不能只是了解个概念，还是要下手尝试才能有更深刻的认知。

想起来我大学转专业的时候，想先练习一点编程的技巧，就找了一本 C++ 教程来看。因为那时候周围没有同行，没人指点，每天苦哈哈学 C++ 的各种概念和写一点 CMD 程序，总是提不起兴趣。直到我了解到 Java 和 Web 前端，突然能直接而快速地感受到构建的快乐，才学了下去。也感谢当时那位在网上讲 Java 课的老师，除了编程语言、设计模式、外围的知识以外，还把 Hacker 文化带给了我，让我工作的时候还能充满快乐而不觉得枯燥。

再回到主题，今年年初到现在也一直在折腾 [Vibe Coding 的一些小项目](https://hualet.org/posts/recent_projects/)，之后其实也一直没有停，还折腾了几个自己做的记忆系统、语音输入法等，虽然这些项目的代码都不是我写的，但是记忆系统中的记忆分类、提取方案、存储方案，以及语音输入法中的 VAD 问题，我也都遇到过并做了思考，不然我可能很难与书中相关章节的技术内容产生共鸣。

前几年一直在管理方面下功夫，感觉颇有收获。今年明显感觉在技术视野上有些力不从心，所以翻过头来继续做一些技术面的补充。虽说如此，一直以来我都避免太陷入技术底层，能做到产品规划/设计的时候够用即可，但是大模型和智能体这个领域的技术太新，如果对底层没有认知就去做，基本上就是撞运气。跌跌撞撞到现在，突然想起很早以前一位朋友说的：新技术还是要学的，哪怕不用！

对了，这本书里面提到的《图解大模型》也是一本理解大模型的好书，通过偏直白的方式让我这个门外汉理解了大模型的底层原理，在几个课题中都受益匪浅，推荐给大家。
